This runbook documents three live production failure recovery drills executed against the 3-node `kubeadm` cluster (`k8s-cp-01`, `k8s-worker-01`, `k8s-worker-02`).

| Drill | Injected Failure Command (Break) | Observable Failure Symptoms & Log Diagnosis | Exact Terminal Recovery Commands (Fix) |
| :--- | :--- | :--- | :--- |
| **Drill 1: Corrupted API Server Static Pod Manifest** | `sudo sed -i 's/--etcd-servers=https:\/\/127.0.0.1:2379/--etcd-servers=https:\/\/127.0.0.1:2389/' /etc/kubernetes/manifests/kube-apiserver.yaml` | `kubectl get nodes` returns `The connection to the server 192.168.56.10:6443 was refused`. Running `sudo crictl ps -a \| grep kube-apiserver` shows `Exited`, and `sudo crictl logs <CONTAINER_ID>` reveals `context deadline exceeded` dialing `127.0.0.1:2389`. | `sudo vi /etc/kubernetes/manifests/kube-apiserver.yaml` -> restore `--etcd-servers=https://127.0.0.1:2379` -> verify static pod auto-restart via `sudo crictl ps \| grep kube-apiserver` and `kubectl get nodes`. |
| **Drill 2: Broken Kubelet Systemd Service Configuration** | `sudo sed -i 's|/usr/bin/kubelet|/usr/local/bin/kubelet-broken|' /lib/systemd/system/kubelet.service && sudo systemctl daemon-reload && sudo systemctl restart kubelet` | Node transitions to `NotReady` in `kubectl get nodes`. On the affected node, `sudo systemctl status kubelet` shows `Active: activating (auto-restart) (Result: exit-code)` with `status=203/EXEC`, and `sudo journalctl -xeu kubelet` logs `Failed to locate executable /usr/local/bin/kubelet-broken: No such file or directory`. | `sudo sed -i 's|/usr/local/bin/kubelet-broken|/usr/bin/kubelet|' /lib/systemd/system/kubelet.service && sudo systemctl daemon-reload && sudo systemctl restart kubelet && sudo systemctl status kubelet`. |
| **Drill 3: Expired Cluster PKI Certificates** | Simulate clock skew past 1-year validity (`sudo timedatectl set-ntp false && sudo date -s "+400 days"`) or inspect expiring control-plane certs | `kubectl` commands fail with `Unable to connect to the server: x509: certificate has expired or is not yet valid`. Running `sudo kubeadm certs check-expiration` confirms `admin.conf`, `apiserver`, and `etcd-server` certificates are expired. | `sudo kubeadm certs renew all` -> copy updated kubeconfig `sudo cp -i /etc/kubernetes/admin.conf $HOME/.kube/config` -> restart control-plane static pods `sudo crictl rm -f $(sudo crictl ps -q --name 'kube-apiserver\|kube-controller-manager\|kube-scheduler\|etcd')`. |
